# 프로젝트 문서

2026-09-10 소스와 체크인 설정 기준으로 정리했다. 기본값은
`project_bringup/project.launch.py` 통합 실행 기준이다. 개별 노드 실행에는
호환용 기본값이 적용되어 파지·주행 동작이 달라질 수 있다.

| 문서 | 읽는 목적 |
| --- | --- |
| [인수인계·실행](HANDOVER.md) | 장비·환경 확인, 시작·중지, 원격 RViz, 현장 인계 |
| [구조와 인터페이스](ARCHITECTURE.md) | 패키지 책임, 좌표계, 임무 흐름, ROS 연결 |
| [설정·캘리브레이션](CONFIGURATION.md) | 설정 위치, 두 프로파일, 스테이션·배출 좌표 |
| [파지 후보와 진단 도구](GRASP_CANDIDATES.md) | 카메라 보정, 몸통 후보, 계획·상공 시험의 차이 |
| [디버깅 로그](DEBUG_LOG_GUIDE.md) | 실행별 로그 선택과 증상별 추적 |
| [개발·검증](DEVELOPMENT.md) | 빌드·테스트, 수정 범위, 이번 정리의 검증 결과 |
| [유지보수·리팩터링 검토](MAINTENANCE.md) | 개선 우선순위, 미확인 사항, 과거 변경 기록 |

처음 인수하면 인수인계 → 설정 → 로그 순서로 읽고, 코드를 변경할 때 구조와
개발 안내를 함께 본다. 과거 계획서·날짜별 세션 기록은 중복/폐기된 동작을 제거해
위 문서로 통합했다. [이전 문서 대응표](MAINTENANCE.md#문서-통합-내역)에서 이동 위치를 찾는다.

`MEMO.md`는 작성자의 원문을 보존한 개인 메모다. 현재 실행 절차는 이 문서 묶음을 기준으로 한다.
예전 로그·시험 수치는 [과거 기록](MAINTENANCE.md#과거-변경에서-남긴-판단-근거)으로 구분하며,
현재 작업 트리에 없는 자료를 남아 있는 증거로 간주하지 않는다.
