# 2026-09-06: 파지 삽입·관측 자세와 위치 보정 기준 수정

## 근거와 범위

분석한 실행은 `cleanup_debug/run_20260905_205744_3446` 및
`motion_debug/run_20260905_205651_3310/telemetry.jsonl`이다.
수정 금지 패키지는 변경하지 않았으며, 실물 이동이나 실제 Gemini 요청으로 시험하지 않는다.

### ID 4 정지

ID 4 스테이션의 네 번째 회전에서 **ID 5**를 다시 관측하며 fault가 발생했다.
당시 변환은 다음과 같다(x/y: m, yaw: rad).

- 기존 map→odom: `(1.972931, 0.769003, -2.669224)`
- 관측 map→odom: `(2.213758, 1.155629, -2.509005)`
- 당시 odom 로봇 위치: `(1.044807, -2.234214)`

변환의 translation 성분끼리 빼면 0.4555m지만, 같은 로봇 점에 두 변환을 적용하면
위치 차이는 약 **0.0616m**, 방향 차이는 약 **0.1602rad**다.
변환 원점의 이동량을 로봇 위치 점프로 간주한 것이 직접적인 오정지 원인이다.
이전 문서의 '0.439/0.455m는 실제 로봇 위치 점프'라는 해석은 이 기록에 대해 정정한다.

### 얕은 파지

실패한 두 목표는 link1 기준 x=0.3466/0.3507m였다. 선호 −60° 자세는 불가능했지만
기존 IK가 −42.5/−40°로 fallback해 reachable=true를 반환했다.
관절 피드백의 모델상 끝단 위치는 목표와 약 1~2mm 차이였으므로,
단순히 팔 이동 시간이 부족했다는 증거는 없다.
관측된 물체 표면을 그대로 끝단 목표로 사용하고 별도 삽입 동작이 없었다.
물리적 TCP/카메라 보정 오차와 실제 접촉 상태까지 이 기록으로 확정할 수는 없다.

## 구현

### 로봇 위치 기준 보정

공통 `localization_policy` 함수로 아래 값을 계산한다.

`position_error = norm(T_measured * p_odom_robot - T_filtered * p_odom_robot)`

- localizer는 이미지 시각의 odom 위치를 사용한다. 후보 일관성 검사도 같은 기준이다.
- EMA는 로봇 위치에서 translation과 yaw를 제한한 뒤 map→odom을 재구성한다.
  translation/yaw를 원점에서 각각 제한해서 발생할 수 있는 인공적인 로봇 이동을 피한다.
- guard도 같은 로봇 점에 두 변환을 적용한다. odom TF 신선도도 검사한다.
- 기존 위치/방향 안전 한도는 올리지 않는다. 실제 0.5m 로봇 점프는 여전히 차단한다.
- 진단 JSON에 `robot_position_error`와 `offset_translation_error`를 함께 남긴다.
- 회전 취소 로그의 `shutdown` 오표기는 `cancel requested`로 구분한다.

엔코더와 시각 관측의 누적 방향 차이까지 자동 보정한 것은 아니다.
스테이션 0의 한 바퀴 전후 같은 마커에서 약 12° 차이가 있었으므로,
반복 실측 후 바퀴 상수/미끄러짐/카메라 추정을 분리해야 한다.

### 공통 파지 계획

`pick_and_place::planGrasp`가 **도달 가능 판정과 실제 실행 모두**의 계획을 생성한다.

- 허용 접근 pitch: −65°~−55° (−60° 우선). 얕은 각도로 바꿔서 reachable을 통과시키지 않는다.
- 기본 삽입 깊이: tool 진행축으로 **0.012m**. 파라미터 `grasp_insertion_depth` 범위 0~0.025m.
- `floor_height` 기본 map z=0.0m. 삽입 후 끝단이 바닥에서 최소 0.012m 위에 있어야 한다.
- 모든 단계의 IK를 사전에 검증: pregrasp → 표면까지 하강 10점 → 삽입 4점 → 인양 10점.
  각 구간은 시간순 다중 관절 목표로 실행하며, 삽입 완료 전에 그리퍼를 닫지 않는다.
- 인양을 포함한 전체 계획이 없으면 추가 베이스 접근을 제안한다. 도착 오차 +2cm에서도
  전체 계획이 가능한 위치를 선택한다. 기존 접근 횟수·거리 제한과 충돌 정지는 유지한다.
- 삽입/인양 실패를 성공으로 보고하지 않는다. `SEQUENCE_COMPLETE`는 명령 실행 완료이며,
  실제 물체 수거 성공은 manager의 시각 확인이 담당한다.

12mm는 첫 실물 검증용 기본값이다. TCP 실측이나 물체 두께를 자동 보정하는 값은 아니다.
허용한 pitch와 바닥 높이는 평평한 현재 시험 환경 기준이며, 불명확한 환경에서는 재설정해야 한다.

### 가까운 물체 재관측

- `/observe_floor`는 기본 초기 자세에서 손목만 +0.20rad 내려 보는 임시 관측 자세다.
- manager가 목표 재검출 전에 이 자세의 도착을 기다리고 350ms 정착 후 촬영한다.
- 브링업 초기 자세와 `/park_arm`은 기존 `[0, -0.523, -0.523, 1.5707]` 그대로다.
- 파지 후 물체가 남으면 옛 앵커/잘린 확인 이미지를 재사용하지 않고,
  임시 관측 자세에서 새로운 전체 마스크 관측(`249`)을 얻어 재평가한다.
- 여전히 중심이 확인되지 않으면 집지 않는다. 무조건 후진하거나 맹목적으로 삽입하지 않는다.
- `/pick/events`에 PLAN/OPEN/PREGRASP/DESCEND/INSERT/CLOSE/LIFT/RETURN_HOME 단계 기록을 추가했다.

## 영상 저장

`robot_motion/grasp_video_recorder`는 별도 읽기 전용 노드다.
통합 브링업에 기본 포함되며 물체 선택/접근/파지 이벤트가 있을 때만 저장한다.
YOLO가 아무것도 찾지 못한 스캔만으로는 영상 저장을 시작하지 않는다.

```text
motion_debug/video_YYYYMMDD_HHMMSS_microseconds/
  clip_001_<object_uuid>.avi
  clip_001_<object_uuid>.frames.jsonl
```

- MJPEG AVI, 960×540, 최대 약 10fps. 결과 확인/실패 후 3초 추가 기록.
- 파일은 최대 90초마다 분리한다. 이미지·이벤트가 끊겨도 기록 활성 시간은 유한하다.
- sidecar에는 프레임 번호, 원본 이미지 시각, UUID, 최근 작업/팔 단계가 들어간다.
  누락 프레임이 있으면 영상 재생 시간 대신 `image_stamp`로 telemetry와 맞춘다.
- 최신 프레임 하나만 보관하며 변환·인코딩·파일 쓰기는 별도 writer thread에서 한다.
- 여유 공간 1GiB, 해당 녹화 노드 실행의 저장량 약 512MiB에서 기록을 중지한다.
  기존 영상은 자동 삭제하지 않는다. 디스크/코덱 실패는 녹화만 비활성화한다.
- 저장 해제: `ros2 launch project_bringup project.launch.py record_grasp_video:=false`

손목 카메라 영상은 접촉 순간 그리퍼 전체를 보여주지 못할 수 있다.
기록이 부족하면 외부 고정 카메라 영상이 추가로 필요하지만, 이번 변경은 기존 카메라만 사용한다.
